## Overview

Android health applications can process highly sensitive personal information, including medical records, reproductive health information, and mental health data.

Security analysis tools such as MobSF identify technical indicators, but their results can be difficult for nontechnical users to understand.

**Health App Privacy Explainer** makes selected security findings more accessible by combining deterministic Python analysis with explanations generated by Meta Muse Spark 1.3.

The application classifies Android permissions and third-party SDK indicators, presents structured findings, and uses Meta AI to explain what the available evidence does and does not establish.

This project builds upon my ongoing undergraduate cybersecurity research at Kent State University.

## The Problem

A security report may identify permissions such as `CAMERA`, `RECORD_AUDIO`, or `ACCESS_FINE_LOCATION`, alongside third-party analytics, advertising, and crash-reporting SDK indicators.

However, these findings alone do not prove that an application collects, transmits, or shares sensitive information.

Users and researchers need a way to understand:

- What identified permissions allow.
- Why certain SDK indicators deserve attention.
- Which findings are supported by technical evidence.
- What behavior remains unverified.
- What additional investigation may be appropriate.

## Our Solution

The application follows this workflow:

**MobSF-style JSON → Python Analysis Engine → Meta Muse Spark 1.3 → Streamlit Dashboard**

The Python analysis engine uses predefined rules to classify permissions and third-party SDK indicators.

Meta Muse Spark 1.3 generates plain-English explanations that distinguish directly observed findings from unverified possibilities and recommend additional checks.

The Streamlit dashboard presents the technical findings, AI-generated interpretations, and a downloadable structured analysis report.

### What Makes This Project Different?

The goal is not simply to summarize a security report with AI.

The system combines:

1. **Deterministic analysis** to classify technical indicators.
2. **Meta AI interpretation** to explain the meaning and limitations of those findings.
3. **Evidence-aware communication** to avoid unsupported claims about application behavior.

By separating technical observations from interpretations, the application supports more responsible security analysis.

## Features

### 1. JSON Report Upload

- Upload supported JSON reports.
- Extract available application metadata.
- Identify permission declarations.
- Extract supported third-party SDK indicators.
- Display summary counts.
- Handle invalid JSON input.

**Current limitation:** JSON ingestion has been tested using synthetic MobSF-style reports. Compatibility with actual MobSF exports requires further validation.

### 2. Android Permission Analysis

- Classifies selected Android permissions by functionality.
- Identifies permissions marked privacy-sensitive under predefined research rules.
- Flags unrecognized permissions for further review.
- Generates permission summary statistics.

Supported categories include camera/media, microphone, location, contacts, accounts, storage, device information, network, and system functionality.

Privacy-sensitive classification does not establish actual permission usage or malicious activity.

### 3. Third-Party SDK Analysis

The system recognizes selected third-party SDK indicators, including:

- AppsFlyer
- Firebase Analytics
- Google Crashlytics
- AdMob
- Localytics
- Prebid Mobile
- Amazon Advertisement

Recognized indicators are categorized by their primary functions, including analytics, advertising, attribution, and crash reporting.

Unknown entries are flagged for further examination.

An SDK indicator does not independently confirm that the associated SDK transmitted data.

### 4. Meta AI-Powered Privacy Explanations

The project integrates **Meta Muse Spark 1.3 through Meta Model API**.

The model receives structured findings generated by the Python analysis engine and produces understandable explanations.

Its responses cover four sections:

**Overview**

Summarizes the technical findings.

**Confirmed Technical Indicators**

Identifies permissions and SDK indicators directly present in the supplied report.

**Unconfirmed Possibilities**

Explains potential privacy implications without presenting them as verified application behavior.

**Recommended Verification**

Suggests additional checks, such as:

- Reviewing Android runtime permission requests.
- Examining application functionality.
- Comparing findings with privacy disclosures.
- Performing manual code inspection.
- Conducting dynamic network analysis when appropriate.

The model is explicitly instructed not to invent permissions, SDKs, or evidence, or to claim that an application is malicious without proof.

**Integration status:** Meta Muse Spark 1.3 has been successfully integrated and tested through Meta Model API. The application generated a real, evidence-aware privacy explanation using synthetic demonstration data.

### 5. Interactive Streamlit Dashboard

The dashboard provides:

- JSON report upload.
- Application name and package information.
- Total permission count.
- Privacy-sensitive permission count.
- Third-party SDK indicator count.
- Recognized SDK count.
- Permission classification table.
- Third-party SDK classification table.
- Privacy interpretation disclaimer.
- Meta AI explanation generation.
- Downloadable structured analysis report.

The application handles API failures by displaying an error rather than presenting fabricated AI responses.

### 6. Evidence-Aware Interpretation

The project distinguishes three types of information:

**Confirmed Technical Indicator**

A permission declaration or SDK indicator directly identified in the supplied report.

**Unconfirmed Possibility**

A potential privacy implication that cannot be established from the available static findings.

**Recommended Verification**

An additional investigation that could help determine whether a suspected behavior actually occurs.

These distinctions are especially important when examining applications that may handle sensitive health information.

## Installation and Setup

### Step 1: Clone the Repository

```bash
git clone https://github.com/mirakhatun-cs/health-app-privacy-analyzer.git
cd health-app-privacy-analyzer
```

### Step 2: Install Dependencies

Python 3 is required.

```bash
python -m pip install streamlit openai
```

### Step 3: Configure Meta Model API

Create an API key through Meta's developer platform:

https://dev.meta.ai/

Configure the environment variable:

`MODEL_API_KEY`

For GitHub Codespaces, use Codespaces Secrets to store the API key securely.

Never hardcode API credentials or commit them to the public repository.

Meta Model API usage requires an authorized account and may incur charges depending on available credits and billing settings.

### Step 4: Run the Application

```bash
python -m streamlit run app.py
```

In GitHub Codespaces, open the forwarded Streamlit application port.

### Step 5: Upload a JSON Report

Upload the included file:

`sample_mobsf.json`

This file contains synthetic demonstration data and is not an actual scan of a health application.

The application will classify the permissions and SDK indicators contained in the report.

### Step 6: Generate Meta AI Explanations

After uploading the report:

1. Review the permission and SDK findings.
2. Scroll to the **Privacy Interpretation** section.
3. Click **Generate Meta AI Explanation**.
4. Review the explanation generated by Muse Spark 1.3.

The model separates confirmed indicators from unverified possibilities and provides recommended verification steps.

Generating explanations requires active Meta Model API access.

### Step 7: Download the Analysis

Click **Download Analysis (JSON)** to export the structured rule-based findings.

**Note:** The current download contains the deterministic analysis results. AI-generated explanations are displayed in the dashboard but are not yet included in the downloaded JSON.

## Responsible Security Analysis

This tool is designed to identify and explain **potential privacy and security indicators**, not prove malicious or unauthorized behavior.

Important limitations:

- Requested permissions do not prove that an application accesses the associated data.
- SDK indicators do not prove that information is transmitted to third parties.
- Predefined SDK classifications do not independently establish runtime behavior.
- Static findings cannot confirm complete application data flows.
- The tool does not automatically scan APK files.
- The current version does not perform dynamic network monitoring.
- The system does not determine whether an application complies with privacy laws or its privacy policy.
- AI explanations may contain errors and require independent verification.
- Supported JSON structures are limited and need further validation against actual MobSF reports.

The dashboard uses explicit uncertainty labels and provides recommended verification steps to support responsible interpretation.
